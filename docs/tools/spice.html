Why the flagship netlists read higher than the model

The flagship netlists use ideal switches with the GaN on-resistance and no dead time, so ngspice sees conduction losses only: switch Rds(on), inductor DCR, flying-capacitor ESR and PCB copper. The full model adds output-capacitance, dead-time, gate-drive, core and housekeeping losses on top. The test that matters is that ngspice agrees with the conduction-only result from the repository's own circuit simulator to within 0.005 percentage points. It does, in tests/test_flagship_sim.py, which runs on every commit.

Switching losses are not left to SPICE. Ideal-switch models cannot represent output-capacitance energy, and vendor GaN SPICE models are not redistributable here. They come from datasheet charge and energy figures instead; see loss modelling.

The sandbox

A SPICE netlist is code. An ngspice .control block can run shell commands, and .include can read any file. Every netlist therefore passes the same guard, implemented three times and tested against one shared set of cases. The guard runs in this page as JavaScript, in the desktop app as Rust before ngspice starts, and in Python for the test suite. It rejects control blocks, includes, libraries, unknown elements and dot commands, oversized files, and transient runs over five million points. ngspice then runs in batch mode in an empty temporary folder with a cleared environment, a 60-second limit and a 1 MB output cap. Details: SECURITY_MODEL.md.

The web version never executes a netlist. For an unmodified preset it shows the ngspice result stored when the repository was built. Edited netlists run only in the desktop app.
